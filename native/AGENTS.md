# native/ — pinned upstream sources and staged binaries

- `downloaded/` — pinned Vulkan-Headers + VMA tarball cache. **Generated/downloaded content; never hand-edit.** Refreshed by the `-t:Regenerate` targets.
- `ktx/downloaded/KTX-Software-<tag>/` — shallow sparse KTX-Software checkout at the pinned tag. Same rule; the path carries the tag, and earlier clones are removed on a bump.
- `ktx/staged/<rid>/` — the built libktx binary per RID plus its `ktx.version` stamp (a mismatch with `KtxVersion` rebuilds). Binary and stamp are the CI cache; the binary alone is the release artifact. `ktx/include/` carries a committed `ktx.version` the same way.
- `slang/downloaded/` — the pinned Slang release archive plus its extraction scratch. Same rule; the archive's SHA-256 is verified against `Directory.Build.props` before anything is extracted.
- `slang/staged/<rid>/` — the shipped Slang binaries per RID, copied out of that archive (on Linux, renamed — the archive's `libslang.so` is a symlink and a nupkg cannot carry one), plus a `slang.version` stamp that is never packed; a mismatch with `SlangVersion` re-stages. Both the CI cache key and the release artifact.
- `slang/tool/<rid>/` — the build-time `slangc` (plus the libraries it loads) per RID, copied out of the same archive by `StageSlangCompiler` with a `slangc.version` stamp. The samples and tests compile their shaders with it (#171). Never packed, never uploaded; cached in CI next to `slang/staged/<rid>/` only so a cache hit does not re-download. See `src/Ahjo.Vulkan.Slang.Native/AGENTS.md`.
- `slang/include/` — the three headers `tools/generate-slang.rsp` parses. Staged from the archive but **committed**: they are the generator input of record, so a version bump shows the API diff before the generated output is re-derived from it. Their committed `slang.version` stamp is what makes a bump re-stage them (#256); `vma/include/` carries a committed `vma.version` the same way.
- `slang/SLANG-LICENSE.txt` — Slang's Apache-2.0 WITH LLVM-exception text, copied out of the archive and packed into the nupkg. Committed for the same reason: the publish job packs from downloaded artifacts and never runs the fetch.
- `vma/` — the VMA implementation translation unit + `CMakeLists.txt` (hand-maintained, edits allowed).
- `ngx/` — the pinned NVIDIA DLSS (NGX) SDK input, fetched per-file by `tools/setup-ngx.ps1` at the `NgxVersion` tag and verified against `ngx/pins.sha256`. `ngx/include/`, `ngx/NGX-LICENSE.txt` and `ngx/pins.sha256` are committed; `ngx/downloaded/`, `ngx/staged/` (static client libs + the `nvngx_dlss` **and** `nvngx_dlssg` feature DLLs) and `ngx/doc/` are not. The script writes `ngx/staged/<rid>/ngx.version`, and the build refuses a staged SDK whose stamp is missing or differs from `NgxVersion` (#256). The feature DLLs are consumer-supplied by decision (#214): never commit them, never pack them, never stage them under a `lib/` path (the `.gitignore` un-ignores `native/**/lib/**/*.dll`). See `ngx/README.md`.
- `ngx/src/` — the `ahjo_ngx` shim translation unit, its header (which is also `tools/generate-ngx.rsp`'s parse root), the `.def`/`.map` export lists and `CMakeLists.txt`. Hand-maintained, edits allowed — but the export list is written in three places and `NgxExportDriftTests` is what keeps them equal.
- `include/`, `stubs/`, `ktx/stubs/`, `slang/stubs/`, `ngx/stubs/` — hand-maintained build support. The `stubs/` trees are parse-time shims that let libclang read the upstream headers without a system C toolchain, so generated output is a function of the version pin and not of who ran the regen.

Version pins live in `Directory.Build.props`. To move a pin, use `/regen-bindings`. Slang's pin is two values — the tag **and** both archive checksums.
